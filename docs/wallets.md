# Wallets

What to know about the wallets, besides the docs of each function in [monero_c_wallet.h](https://github.com/libmonero/monero-c/blob/main/src/wallet/monero_c_wallet.h):

- **Regtest.** A wallet on a regtest chain has the network type `MONERO_UTILS_NETWORK_REGTEST` (3). It is a mainnet wallet with the regtest flag of monero-cpp, so its addresses are those of mainnet, and a random one scans from the first block and not from the height of the node. The node runs with `--fixed-difficulty=1`, as the compose file of the integration tests does, or `monero_daemon_generate_blocks()` times out.
- **Sync from a height.** `monero_wallet_sync()` with a start height fetches the blocks from there to the end of the chain, so `numBlocksFetched` is the height of the chain minus the start, on a chain of any length. A start height below the last block that the wallet processed is ignored, so a wallet that has synced can't be used to try another one.
- **Height of the daemon.** wallet2 keeps the height of the daemon, and the greatest height of its peers, for 30 seconds. `monero_wallet_get_daemon_height()`, `monero_wallet_get_daemon_max_peer_height()` and `monero_wallet_is_daemon_synced()` can be 30 seconds late, after mining blocks on a regtest node for instance.
- **A sync that does nothing.** `monero_wallet_sync()` fetches no block, and reports no error, while `monero_wallet_is_daemon_synced()` is false: the height of the daemon is lower than the greatest height of its peers, or it is 1. A regtest chain that has only the genesis block is never synced, and with the 30 seconds above, a wallet that was created on it and then got blocks syncs none of them for up to 30 seconds. Mine one block before the wallet is created, or wait.
- **Callbacks.** `monero_wallet_sync()`, `monero_wallet_scan_txs()`, `monero_wallet_rescan_blockchain()` and `monero_wallet_close()` return after the callbacks that they caused have returned. A rescan tells the listeners of the outputs that it finds again, and no block or progress.
- **Files in memory.** `monero_wallet_get_keys_file_buffer()` and `monero_wallet_get_cache_file_buffer()` give the contents of the keys file and of the cache file of a full wallet, and `monero_wallet_open_data()` opens a wallet from them, for a program that keeps its wallets in a database or has no file system. The keys are encrypted with the password of the wallet, `view_only` leaves the spend key out, and the cache can be left out when the wallet is opened, which then scans again from its restore height. The wallet that is opened has no files, so `monero_wallet_save()` does nothing on it, and it has no daemon connection until `monero_wallet_set_daemon_connection()` gives it one.
- **Accounts.** `monero_wallet_get_account()`, `monero_wallet_get_accounts()` and `monero_wallet_get_subaddresses()` serve every kind of wallet. A wallet of a server filters the accounts by `tag` and leaves the balances of the subaddresses out with `skip_balances`, which saves a request. A full wallet has no account tags and its balances are in memory, so it lists every account and ignores both.
- **Multisig.** `monero_wallet_get_multisig_info()` gives zeros for a wallet that is not multisig.
